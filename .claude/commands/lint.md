# Lint

Полные правила в `CLAUDE.md`, секция "Workflow: Lint".

## Что проверить

1. **Битые wiki-links** — `[[foo]]` в страницах без соответствующего файла `pages/.../foo.md`.
2. **Осиротевшие страницы** — на страницу никто не ссылается из других `pages/`.
3. **Stub-страницы старше 30 дней** — `status: stub` и `created` старше месяца, не двинулись.
4. **Дубликаты** — две страницы про одну сущность под разными именами / в разных категориях.
5. **Противоречия** — одна и та же сущность даёт разные числа / факты в разных страницах. Особенно важно для `metrics/`.
6. **Frontmatter** — отсутствующий, невалидный, или `updated` не совпадает с реальной правкой.
7. **Битые `sources` ссылки** — `sources: [...]` в frontmatter, но файла нет в `sources/`.

## Как делать

1. Прочитай `index.md` — список всех страниц.
2. Прогони Grep по wiki-links, сверь со списком файлов.
3. Прочитай frontmatter каждой страницы (можно батчами).
4. Сохрани отчёт в `queries/YYYY-MM-DD-lint.md`:
   ```yaml
   ---
   title: Lint YYYY-MM-DD
   type: lint
   date: YYYY-MM-DD
   ---
   ```

   ## Найдено
   - **Битые ссылки** (N): список с указанием файла и битой ссылки
   - **Осиротевшие** (N): список
   - **Старые stub'ы** (N): список с датами создания
   - **Дубликаты** (N): пары
   - **Противоречия** (N): описание
   - **Битый frontmatter** (N): список

   ## Предложения
   - Для каждой проблемы — конкретное действие.

5. **НЕ правь автоматически** ничего, кроме мелочей вроде обновления `updated` поля. Все содержательные правки — после подтверждения пользователя.

6. Допиши в `log.md`:
   ```
   YYYY-MM-DD HH:MM LINT → queries/YYYY-MM-DD-lint.md (N issues)
   ```

7. Покажи краткое резюме: сколько проблем по каждой категории, спроси что чинить.
