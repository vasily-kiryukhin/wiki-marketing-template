# Ingest

Обработай источник: $ARGUMENTS

Шаги (см. полные правила в `CLAUDE.md`, секция "Workflow: Ingest"):

1. **Прочитай источник полностью** через Read.
   - Если передан URL — сначала сохрани в `sources/web/<slug>.md` с метаданными (URL, дата, автор), потом читай локально.

2. **Покажи план** перед изменениями:
   - Какие сущности извлёк (концепты, бренды, люди, метрики, каналы, аудитории).
   - Какие страницы планируешь создать (с типом из `pages/_templates/`).
   - Какие существующие страницы планируешь обновить.
   - Дождись «ок» от пользователя.

3. **Создай / обнови страницы** в `pages/`:
   - Для новой — копируй соответствующий шаблон из `pages/_templates/`, заполни frontmatter, заполни содержимое.
   - Для существующей — добавь новые факты, не дублируй уже сказанное. Обнови `updated`, добавь источник в `sources` frontmatter.
   - Расставь `[[wiki-links]]` на упомянутые сущности.

4. **Обнови `index.md`** — добавь новые страницы в нужные секции (по типу).

5. **Допиши строку в `log.md`**:
   ```
   YYYY-MM-DD HH:MM INGEST sources/.../foo.md → pages/concepts/jtbd.md (updated), pages/people/clayton-christensen.md (created)
   ```

6. **Закоммить**:
   ```bash
   git -C . add -A && git -C . commit -m "ingest: <короткое название источника>"
   ```

7. **Краткое резюме пользователю**: какие файлы тронуты, что нового узнали.

## Принципы

- Не плоди десятки stub'ов с двумя строками — лучше упомяни сущность в существующей странице со ссылкой и stub-комментарием.
- Не отвечай на вопросы по источнику до ingest'а — сначала разнеси по wiki.
- Если источник большой (книга, длинный отчёт) — обрабатывай главами / секциями, отдельные коммиты.
